Editorial choices

  • Plain-language headlines (for example the eight Toronto limits and the four Phase 2 design decisions) are this site's wording. The source wording is shown with each one, and links go to the full files.
  • Status badges use deliberately modest labels: Study complete (with limits) Code only, synthetic data Output produced, not yet interpreted Idea, unverified.
  • On the Data sources page, the publisher filter groups the free-text publisher field by organisation, and the "Checked" column groups the provenance field into "Opened and verified" and "Not fully verified". The full original text is shown in each row.
  • On the Phase 2 page, which step each module sits under is this site's reading of the module descriptions.
  • On the Ideas page, the README's phrase "the Phase 2 pipeline below" is turned into a link to the Phase 2 page.
  • Hamilton numbers that the source does not explain are labelled "Unexplained in the source" rather than given an explanation.
  • Not included: the two large Hamilton .csv.gz tables, the Hamilton web map and its data, the 25 individual validation mismatches, and the Phase 1 and Phase 2 code. All are linked instead.
  • The Hamilton README links to a step-by-step LOG.md one folder up; that file is not present at the commit read.

Rebuilding the data

The pages read docs/data/site-data.js, which docs/build_data.py generates from the source files by running git show at the pinned commits. To refresh it, run these from the repository root:

git fetch origin
python3 docs/build_data.py            # the pinned commits
python3 docs/build_data.py --latest   # the branches' current tips

After --latest, update the commit list and snapshot date at the top of build_data.py so the record stays accurate, then re-run the checks in docs/checks/. Those checks compare every number shown on the site with the source files, test the internal links, and click through the interactive parts in a headless browser.
